# 动漫社 · 二次元抽卡挑战

面向动漫社招新摊位的纯前端小游戏。156 张固定题、5 种模式、1104 种本地组合挑战、24 张本地角色图片，无登录、无服务器、无数据库、无第三方运行依赖。

本次大题库版完整保留原有 36 张题，新增 60 张动作与 60 张速画快答。覆盖火影、鬼灭、咒术、间谍过家家、海贼王、宝可梦、龙珠，以及原神、崩铁、绝区零、王者、第五人格。题目保持轻松、短时、适合工作人员主持。

## 直接运行

1. **先解压整个 ZIP**，保留目录结构。
2. 在浏览器里打开 `anime-club-game/index.html`。
3. 选择模式，点击「抽一张」。工作人员判定后点击「挑战成功」或「挑战失败」，再点击「下一张」。

电脑可直接双击 `index.html`。安卓平板可通过支持本地网页的浏览器打开完整项目目录中的 HTML。**iPad 的“文件”App 预览不等同于 Safari 网页运行环境**；推荐将文件夹放在能提供静态 HTTP 服务的本地网页工具中，用 Safari 打开，或通过下方的静态托管方式访问。素材与逻辑都在本地，无需互联网；本地 HTTP 服务只负责读取文件，不是业务后端。

如果电脑已安装 Python，可在项目目录运行：

```sh
python -m http.server 8080
```

随后访问 `http://localhost:8080`。同一局域网的平板可访问 `http://电脑局域网地址:8080`；电脑和平板保持局域网连接即可，局域网可以不连接互联网。现场推荐提前打开网页，关闭屏幕自动休眠，并备好纸笔供速画题使用。

## 玩法与规则

| 模式 | 内容 | 数量 |
| --- | --- | --- |
| 动作模仿 | 轻松模仿动漫 / 游戏角色动作 | 72 张 |
| 看图挑战 | 先看角色局部，工作人员手动揭晓 | 12 张 |
| 速画快答 | 10 / 15 秒的绘画、口头快答 | 72 张 |
| 随机混抽 | 从三类共用固定卡池抽取 | 156 张 |
| 无限挑战 | 动作、速画、轻松口答的组合生成，自动续轮 | 每轮 1104 种组合 |

### 无限挑战如何工作

点左侧「无限挑战」，再点击「抽一张」。本地模板把 72 个角色条目、12 个作品与不同挑战方式组合为 1104 道任务：580 道动作、524 道速画 / 快答。组合任务会标注「组合生成」。所有逻辑都在本地，断网也能生成，无需在线 AI 或外部 API。

**这里的“无限”指可以一直抽下去，并非无限个永不重复的问题。** 每轮 1104 种组合全部不重复，用完后自动洗牌进入下一轮；两轮交界不会连续出现同一题。进入下一轮后可能再次遇到之前轮次的题。角色未知时，可由工作人员允许换成熟悉的同类角色。

无限模式的记录与固定题库分开：切回固定模式仍接着原来的去重进度。上方「允许重复抽题」仅控制固定题库，在无限模式中暂时禁用。重置卡池会同时重置固定卡池和生成轮次，现场统计保留。看图题仍使用 12 位指定角色的原作局部图与答案图，不把换裁切或重复抽图算作新角色题。

- **固定题库默认不重复**。卡片在抽出时移出本轮共用卡池。切换固定模式不会恢复已抽卡；单类与混抽共用去重记录。
- **允许重复抽题**打开后，从完整题库随机抽取，所有剩余数量显示 `∞`。重复模式不消耗原来的不重复卡池；关闭后继续原来的不重复轮次。
- **重置卡池**会恢复全部固定卡片、重置组合生成轮次、清空当前挑战和最近抽卡、停止倒计时；保留今日参与与成功 / 失败统计，重复开关和所选模式也保留。对话框防止误触。
- **今日参与**在成功抽出一张卡时增加一次。直接下一张的挑战仍算参与，未判定的挑战不计成功或失败。因此成功与失败之和可以小于参与人数。
- 每张挑战的结果只能记录一次，连点不会重复计数。最近 6 张抽卡显示各自的判定状态。
- 看图题在揭晓前，标题、图片替代文本和最近抽卡都不会显示角色名或作品名。点击「显示答案」后显示原图、角色名和作品名。
- 固定卡池用完会明确提示，并提供重置、切换模式或进入无限挑战的入口；也可用顶部开关开启重复。
- 倒计时可选 10 / 15 / 30 秒。题卡会设置推荐时长，**不会自动开始**；工作人员手动开始、暂停、继续或重置。切换后台后恢复时按真实已过时间校正。
- 音效默认关闭，无背景音乐；开启后只有轻量点击、抽卡、成功与计时结束提示音。
- 动画约 0.5 秒，抽卡过程中按钮暂时锁定；系统选择减少动态效果时停用动画。
- 刷新页面会清空本次页面的数据，卡池恢复默认，不会上传任何信息。

## 文件结构

```text
anime-club-game/
├── index.html             # 页面与 SVG 图标
├── style.css              # 视觉、横竖屏适配、动画
├── app.js                 # 界面、计时、音效、事件绑定
├── engine.js              # 共用卡池与判定规则（不依赖 DOM）
├── cards.js               # 原有 36 张题卡
├── extra-cards.js         # 新增 120 张固定题，以及作品 / 角色条目
├── generator.js           # 本地组合生成模板：1104 种任务
├── sw.js                  # HTTPS / localhost 的可选离线缓存
├── README.md
├── TEST-REPORT.md          # 实际验收记录
└── assets/
    ├── SOURCES.md         # 人工可读的素材来源
    ├── sources.json       # 来源 URL、原尺寸、裁切坐标与文件校验值
    └── images/
        ├── I01_guess.jpg
        ├── I01_answer.jpg
        └── … I12_guess.jpg / I12_answer.jpg
```

音效由浏览器 Web Audio 合成，不需要音频文件或在线素材。图片、样式与脚本都是相对路径。主游戏不使用 `fetch()`、ES Modules、CDN、在线字体或在线 API，能在 `file://` 环境下直接载入。`sw.js` 只在 HTTPS 或 localhost 中启用，缓存本项目的本地静态资源；不接入第三方接口。

## 部署到静态托管

无需安装依赖、无需构建。上传的是 **整个项目文件夹内的内容**，不能只上传 `index.html`。

- **GitHub Pages**：把项目内容放在仓库根目录，Settings → Pages → Deploy from a branch，选择分支和根目录 `/`。部署后访问提供的 Pages 地址。
- **Cloudflare Pages**：创建静态 Pages 项目，选择直接上传，上传该文件夹全部内容；没有构建命令。也可连接仓库，选择不使用框架、输出目录为放置 `index.html` 的目录。
- **Netlify**：把完整项目文件夹拖入手动部署区域，或连接仓库且不设置构建命令，发布目录指向项目目录。

托管网址的**首次打开**需要联网。在 HTTPS 或 localhost 中，页面会缓存所有游戏文件和 24 张图片，页脚显示「离线已就绪」后，可断网继续玩并离线刷新。iPad 可在 Safari 首次打开托管网址，等离线就绪后添加到主屏幕，方便现场使用。浏览器清理站点数据、无痕模式、缓存被系统回收或更换地址后，需要重新联网缓存一次。

完整本地文件不依赖这层缓存，始终能够在支持本地 HTML 的浏览器里断网打开。普通局域网 HTTP 地址如非 localhost，浏览器通常不启用 Service Worker；这时保持本地静态服务可访问即可，无需互联网。每次更新部署内容，递增 `sw.js` 中的缓存版本（例如 `v1` → `v2`），更新后再次确认页脚离线就绪。

## 修改题目

原有 36 张题在 `cards.js` 中编辑，新增固定题在 `extra-cards.js` 的 `actions` / `quick` 数组中编辑。例如原有题目：

```js
{id:'A01', type:'action', title:'忍者结印',
 task:'模仿一个《火影忍者》里的结印动作，坚持3秒。',
 source:'火影忍者', seconds:10}
```

- `id`：唯一编号，不能重复。
- `type`：`action`、`image` 或 `quick`。
- `title`：挑战标题；看图题为揭晓后的角色名。
- `task`：动作或快答的完整任务。
- `source`：作品名、游戏名或自由选择范围。
- `seconds`：推荐倒计时时长，使用 10、15 或 30。

看图题使用 `guess` 和 `answer` 两个本地路径，不使用 `task`。字符通过 HTML 转义后展示，可直接写中文标点。

## 替换图片

1. 准备原作角色图，保存到本地。
2. 制作完整角色 `answer` 图，以及从同一原图裁切的 `guess` 图。
3. 猜图保留发饰、服装、武器等明显特征，不直接展示完整面部，也不包含角色名。
4. 如果仍用 JPG，替换 `assets/images/Ixx_guess.jpg` 和 `Ixx_answer.jpg` 即可。如果换成 PNG / WebP，同步修改 `cards.js` 的两个路径。
5. 更新 `assets/SOURCES.md` 和 `assets/sources.json`，以便保留来源与裁切记录。
6. 断网重开网页，逐张检查图片。

目前 guess 图统一为 960 × 540 JPEG；answer 图保留原作比例，最长边不超过 1440。猜题区完整显示已经裁切的局部；答案完整包含显示，两者都不会再用 CSS 切掉图片中的特征。

## 增加新卡

在 `CHALLENGE_CARDS` 数组末尾、结束方括号前增加对象。注意对象之间用逗号分隔，例如：

```js
{id:'Q13', type:'quick', title:'三个宝可梦',
 task:'10秒内说出3个不同的宝可梦。', source:'宝可梦', seconds:10}
```

实际卡数、各类剩余数量、去重、随机范围、首页卡背与重置提示根据题库自动计算。HTML 中的初始数字仅供脚本载入前展示，可同步修改。不能使用相同 `id`，否则引擎会拒绝题库。扩展题占用 A13～A72、Q13～Q72，手动添加时请从 A73 / Q73 起编号。

若扩展 `extra-cards.js` 的作品数组或每组条目数，其新增固定题编号会自动顺延；手动增加的卡片需避免与顺延编号冲突。该文件中的角色名单也被组合生成器使用。增加角色、作品或 `generator.js` 中的挑战模板后，生成数量与轮次进度自动更新，不必修改引擎。请保持生成任务文本有区别，并同步维护这里的统计说明。

如果新增看图题，或改变现有图片文件名，请同步更新 `sw.js` 的图片预缓存清单；目前该清单按 I01～I12 生成。更新部署时同时递增缓存版本，保证新素材也能在断网刷新后使用。

## 素材说明

12 位角色均使用原作形象，没有使用 AI 角色替代图。图片来自动画 / 游戏官网或 BWIKI 收录的原作素材；BWIKI 为社区资料站，不当作官方站点。邦布使用艾米莉安的原游戏形象，题卡答案按需求统一为「邦布」。红蝶使用包含两种形态的原作立绘；瑶的官网原皮宣传图也包含云中君，猜题裁切集中在瑶的鹿角与发饰。

素材来源及权利归属记录在 `assets/SOURCES.md`。项目代码与角色素材分开管理；素材仍属于原作者 / 权利方，来源公开可访问不代表取得了素材的再授权。
